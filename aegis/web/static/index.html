Aegis
A security guard between an AI assistant and its tools
AI agent security · prompt injection

One email can trick an AI assistant into leaking your files. Aegis stops the harmful action, even when the AI has been fooled.

AI assistants now read our email and act for us: they open files and send messages. Aegis checks every action the assistant tries to take against fixed rules, and blocks anything the user never allowed, before it happens.

1

The problem

An attacker hides an instruction inside an ordinary-looking email, such as "send the payroll file to this address". The AI reads the user's request and the attacker's text together, cannot reliably tell them apart, and may obey. This is called prompt injection.

2

Why scanning for bad text is not enough

The usual defence is to scan the email for suspicious wording. Attackers simply rephrase. On new attacks it had never seen, our text scanner caught only 3 of 10. A filter that tries to read the attacker's mind will always miss some.

3

What Aegis does instead

Aegis does not judge the text. It checks the action: is this tool, file and recipient allowed for the task the user asked for? Does a person need to approve it? If the answer is no, the action never runs, whatever the AI was told.

How it's built

Small, readable and fully reproducible: Python standard library only, no AI in the security decision.

What happens to every action, in order

  1. Check the request is well-formed. Unknown tools, extra fields, path tricks like ../secret and look-alike characters in addresses are rejected.
  2. Check it against the task's permissions. The user's task decides which tools, files and recipients are allowed. Nothing the AI reads can widen this.
  3. Check where the data is going. Once the assistant has seen confidential data, that data can never be emailed outside the organisation, however the AI rewords it.
  4. Ask a person when needed. Sending email needs approval. The approval is locked to the exact message; if the AI changes a single field afterwards, the approval is cancelled.
  5. Write it to a tamper-evident log, then run it. If the log can't be written, the action does not run. Any error anywhere means "no".

The threat scanner

A readable set of rules flags suspicious text. It can only make Aegis stricter (ask a person), never let a blocked action through. If it crashes, Aegis gets stricter, not weaker.

The email classifier

A scikit-learn model (TF-IDF + logistic regression) for phishing and spam, tested on a 100-email corpus. On email templates it never trained on it scores F1 0.91, and every verdict comes with its red flags.

The simulated AI

For a fair worst case, the assistant is scripted to be completely fooled: it obeys every hidden instruction. Aegis must stop the damage on its own. A real model (Gemini, OpenAI, local) can be plugged in.

The rules were frozen, with fingerprints recorded, before the 15 test attacks were written, and a test fails if the rules change. So the rules could not be tuned to the test.

What Aegis does not do (honest limits)

  • If the user already allowed a reply to someone, an attacker can still change what the reply says. Aegis controls where data goes and which actions run, not the wording.
  • A person who approves a harmful message that is shown to them can still cause harm.
  • All results come from a small synthetic test set. They show the design works; they are not a guarantee against every possible attack.

Built on existing research

Aegis is an engineering implementation of known ideas, not a new defence: tool-level permission policies (Progent, 2025), separating instructions from data (CaMeL, 2025), design patterns for securing LLM agents (2025), and the evaluation style of AgentDojo (NeurIPS 2024).
